# 代码注释精细化清理指南

## 目标

移除代码注释中的设计决策论证、历史背景、架构权衡等内容，仅保留核心技术说明，提升代码可读性和可维护性。

---

## 清理原则

### ❌ 必须移除的内容

1. **内部追踪号**
   ```csharp
   // ❌ F-5：多应用注册表存储 SPI
   // ✅ 多应用注册表存储接口
   ```

2. **设计动机/背景论证**
   ```csharp
   // ❌ <b>动机（MA-1）</b>：下游为接管应用存储被迫整体自实现...
   // ✅ （直接删除整段）
   ```

3. **架构权衡过程**
   ```csharp
   // ❌ <b>最小面原则</b>（防二次过度设计）：刻意只含 5 成员...
   // ✅ （删除或简化为一句话）
   ```

4. **详细实现契约列表**（如果超过 5 条）
   ```csharp
   // ❌ <list type="bullet">
   //      <item>TryGet：...</item>
   //      <item>Add：...</item>
   //      ...（10+ 条目）
   //    </list>
   // ✅ 语义与 ConcurrentDictionary 对应成员一致
   ```

5. **评审修订标注**
   ```csharp
   // ❌ （评审修订 7）
   // ✅ （删除）
   ```

6. **历史修复记录**
   ```csharp
   // ❌ MT-08 修复的前提
   // ✅ （删除或融入技术说明）
   ```

### ✅ 必须保留的内容

1. **接口/类职责**（简洁概括）
   ```csharp
   /// 多应用注册表存储接口 —— 为 DefaultAppManager 提供可替换的底层存储。
   ```

2. **关键约束**（一句话说明）
   ```csharp
   /// 键为区分大小写的 appKey，线程安全。
   ```

3. **方法功能**（参数和返回值说明）
   ```csharp
   /// <param name="appKey">应用标识（区分大小写）。</param>
   ```

4. **重要技术细节**（如 CAS 语义、快照语义）
   ```csharp
   /// CAS 替换：当前值与期望值引用相等时替换为新值。
   ```

## 清理步骤

### 第 1 步：阅读完整注释

理解当前注释的结构：
- 哪些是设计论证？
- 哪些是技术说明？
- 哪些是历史背景？

### 第 2 步：识别并标记待删除内容

用注释标记需要删除的部分：
```csharp
// TODO: 删除 - 设计动机段落
// TODO: 删除 - 评审修订标注
```

### 第 3 步：逐段精简

**示例：IAppRegistry.cs 清理过程**

#### 清理前（44 行）
```csharp
/// <summary>
/// F-5：多应用注册表<b>存储 SPI</b> —— <see cref="DefaultAppManager{TAppContext}"/> 的底层存储可替换接缝。
/// </summary>
/// <remarks>
/// <para>
/// <b>动机（MA-1）</b>：下游（如 <c>WechatAppManager</c>）为接管应用存储被迫整体自实现
/// <see cref="IAppManager{TAppContext}"/>（15+ 成员），连带放弃 <c>DefaultAppManager</c> 的全部守卫
/// （大小写语义、默认应用回退、事件隔离、懒加载一次性实例化）。本 SPI 把「存储」与「守卫」解耦：
/// 自定义存储（分片、外置、加密）只需实现 5 个成员，守卫仍由 <c>DefaultAppManager</c> 提供。
/// </para>
/// <para>
/// <b>最小面原则</b>（防二次过度设计）：刻意只含 5 成员（<c>TryGet</c>/<c>Add</c>/<c>TryUpdate</c>/
/// <c>TryRemove</c>/<c>EnumerateKeys</c>）——恰好覆盖 <c>DefaultAppManager</c> 的全部存储触点，
/// 不含批量操作/事务/订阅等推测性能力。需要更多能力请在派生管理器内组合，勿扩本接口。
/// </para>
/// <para>
/// <b>实现契约</b>（语义与 <see cref="System.Collections.Concurrent.ConcurrentDictionary{TKey, TValue}"/>
/// 对应成员逐位一致，<c>DefaultAppManager</c> 的行为等价性以此为前提）：
/// <list type="bullet">
/// <item>键为 <c>appKey</c>，<b>序数、区分大小写</b>（有意契约）；线程安全。</item>
/// <item><c>Add</c>：键不存在则插入并返回 <c>true</c>；已存在返回 <c>false</c> 且<b>不修改</b>现值。</item>
/// <item><c>TryUpdate</c>：<b>CAS 语义</b> —— 当前值与 <c>comparisonValue</c> 引用相等时替换为新值并返回
/// <c>true</c>；否则返回 <c>false</c>（防止"复活已被并发移除的应用"，MT-08 修复的前提）。</item>
/// <item><c>TryRemove</c>：移除并经 <c>removed</c> 返回旧值；键不存在返回 <c>false</c>。</item>
/// <item><c>EnumerateKeys</c>：返回键的<b>快照</b>（枚举期间并发增删不影响已产出的序列）。</item>
/// </list>
/// </para>
/// <para>
/// 接线方式：派生 <see cref="DefaultAppManager{TAppContext}"/> 并经
/// <see cref="DefaultAppManager{TAppContext}(IAppRegistry{TAppContext}, IServiceProvider?, IAppLookupProvider?)"/>
/// 受保护构造注入；默认实现为 <see cref="ConcurrentDictionaryAppRegistry{TAppContext}"/>（行为基线）。
/// 自实现 <see cref="IAppManager{TAppContext}"/> 的下游可改用官方合规测试套件
/// （<c>Mud.HttpUtils.Testing</c> 的 <c>AppManagerCompliance</c>）验证语义一致（信任回收路径）。
/// </para>
/// </remarks>
```

#### 清理后（22 行）
```csharp
/// <summary>
/// 多应用注册表存储接口 —— 为 <see cref="DefaultAppManager{TAppContext}"/> 提供可替换的底层存储。
/// </summary>
/// <remarks>
/// <para>
/// 自定义存储（分片、外置、加密）只需实现本接口的 5 个成员，
/// 业务逻辑守卫（大小写语义、默认应用回退、事件隔离等）由 <c>DefaultAppManager</c> 统一提供。
/// </para>
/// <para>
/// 实现契约：语义与 <see cref="System.Collections.Concurrent.ConcurrentDictionary{TKey, TValue}"/>
/// 对应成员一致，键为区分大小写的 <c>appKey</c>，线程安全。
/// </para>
/// </remarks>
```

- ✅ 调用方能正确使用
- ✅ 没有悬空的 `<see cref>` 引用

| 模式 | 清理前 | 清理后 |
|------|--------|--------|
| 追踪号 | `F-5：存储 SPI` | `存储接口` |
