### 1.3 目标与非目标

**目标**

1. **消除静默失效**：任何「用户已配置但不生效」的情况必须要么生效、要么编译期/启动期报错，不得静默。
2. **收敛配置入口**：同值域多入口必须建立**明确的优先级契约**（文档 + 校验 + 测试三件套）。
3. **统一生效条件表达**：条件生效配置必须由 `IValidateOptions` / `IPostConfigureOptions` / 生成器诊断之一守护。
4. **文档即契约**：README / XML 注释与实现双向对齐，区分「文档滞后」与「代码未实现文档承诺」。
5. **测试可回归**：为每条 CFG 项提供可执行的最小验证用例。

**非目标**

- ❌ 不重构与我们无关的业务逻辑与执行链（如请求执行编排、缓存实现、SSRF 策略实现）。
- ❌ 不引入新第三方依赖。
- ❌ 不为了"统一"而破坏（当前未发布，但 PublicAPI 分析器已启用，所有公开 API 变更仍走正式流程）。
- ❌ 不处理 `03-P2` Roadmap R-4~R-8（端点级弹性策略、成功响应体直方图、AOT 守卫、`ValidateUrlAsync` 异步化）。

## 三、整改原则与不变量

### 3.1 六条原则

1. **不静默原则**：配置被忽略必须产生「编译期诊断 / 启动期校验失败 / 启动期警告日志」三者之一。
2. **单一真相源**：同一语义的默认值/单位只允许定义一处，其余引用或由测试锁定一致性。
3. **配置幂等**：同一配置多次应用结果一致（如 `AllowedDomains` 热更新不得累积）。
4. **不污染共享实例**：`IOptions<T>.Value` 为单例缓存对象，**禁止就地修改**（CFG-01 的核心约束）。
5. **AOT 优先**：新增诊断/校验不得引入 `RequiresUnreferencedCode`/`RequiresDynamicCode`；反射仅允许出现在测试与已标注的绑定路径。
6. **多 TFM 一致**：`netstandard2.0;net6.0;net8.0;net10.0` 四目标行为一致；`#if` 内的成员在低 TFM 缺失属正常，不得判为缺陷。

### 3.2 必须维持的不变量（实施后须有测试守护）

| # | 不变量 | 守护方式 |
| :--- | :--- | :--- |

| I-2 | 方法级弹性策略与全局装饰器**只应用一次**（`SkipResilience` 标记） | 既有 `ResilientHttpClientTests.cs:246-294` |

{
    public static EnhancedHttpClientOptions Clone(EnhancedHttpClientOptions? source)

// 修改 1：QueryParameterBinder.cs:93-106
private static void GenerateQueryParameter(StringBuilder codeBuilder, ParameterInfo param,
    ParameterAttributeInfo attr, string indent)
{
    var prefix = attr.NamedArguments.TryGetValue("Prefix", out var p) && p is string ps && ps.Length > 0
        ? ps : null;
    var treatAsString = attr.NamedArguments.TryGetValue("TreatAsString", out var t) && t is true;
    var serializeNull = attr.NamedArguments.TryGetValue("SerializeNull", out var n) && n is true;

    var paramName = GetQueryParameterName(attr, param.Name);
    var formatString = GetFormatString(attr);

    if (TypeDetectionHelper.IsSimpleType(param.Type))
    {
        // 简单类型：SerializeNull 需要「允许 null 落键」的构造入口
        GenerateSimpleQueryParameter(codeBuilder, param, ApplyPrefix(paramName, prefix),
            formatString, attr, indent, allowNull: serializeNull);
    }
    else
    {
        GenerateComplexQueryParameter(codeBuilder, param, indent, prefix, treatAsString, serializeNull);
    }
}

private static string ApplyPrefix(string name, string? prefix)
    => string.IsNullOrEmpty(prefix) ? name : prefix + "." + name;      // 契约：Prefix="filter" + Name="keyword" => filter.keyword

// 修改 2：GenerateComplexQueryParameter（:156-167）
private static void GenerateComplexQueryParameter(StringBuilder codeBuilder, ParameterInfo param,
    string indent, string? prefix, bool treatAsString, bool serializeNull)
{
    if (TryGenerateInlineQueryFlattening(codeBuilder, param, indent, ",",
            includeNullValues: serializeNull,
            useJsonSerialization: !treatAsString,        // TreatAsString=true ⇒ 走 ToString() 而非 JSON
            urlEncode: true,
            prefix: prefix))                             // ★ 新增形参
        return;

    var prefixLiteral = prefix is null ? "string.Empty" : $"\"{StringEscapeHelper.EscapeString(prefix)}\"";
    var includeNullLiteral   = serializeNull.ToString().ToLowerInvariant();
    var useJsonLiteral       = (!treatAsString).ToString().ToLowerInvariant();
    codeBuilder.AppendLine($"{indent}if ({param.Name} != null)");
    codeBuilder.AppendLine($"{indent}{{");
    codeBuilder.AppendLine($"{indent}    FlattenObjectToQueryParams({param.Name}, {prefixLiteral}, \",\", __queryParams, {includeNullLiteral}, {useJsonLiteral}, true, __rawQueryPairs, 0, _contentSerializer);");
    codeBuilder.AppendLine($"{indent}}}");
}

internal sealed class AllowedDomainsReloader : IDisposable

实际风险：`TokenRecovery` 与 HTTP 重试**不互斥** → 最坏情况请求次数 = `(1 + RecoveryMaxRetries) × (1 + HttpRetries)`。文档未提示。

**设计**

1. **文档**：`Client/README.md` 令牌恢复章节 + `Resilience/README.md` 重试章节分别加入「重试叠加关系图与上限公式」。
2. **启动期提示**：`TokenRecoveryOptions` 侧新增 PostConfigure，当 `RecoveryMaxRetries > 0` 且检测到 `IOptions<ResilienceOptions>.Retry.Enabled` 时记录 **Information**（非警告，避免噪声）说明乘积关系。

```csharp
// 新增：Mud.HttpUtils.Client/TokenManager/TokenRecoveryOptionsPostConfigure.cs
// 依赖 IOptions<ResilienceOptions> —— Client 不引用 Resilience，故改用「按类型名探测」不可行。
// 结论：本项改为【纯文档 + 测试】方案，不做跨包运行时探测（尊重依赖方向约束）。
```
> **架构决策记录（ADR）**：因 `Client` 不能引用 `Resilience`（依赖方向），跨包配置冲突的运行时检测不可行；此类冲突一律由**生成器诊断**（编译期）或**文档契约**承担。本项选后者。

**验证方式（v2.1 复核修订）**：
- **文档**：`Resilience/README.md` 已新增「重试叠加关系」表 + 乘积公式（已实施）。
- **测试（不新增合成"乘积"用例，理由见下）**：两层重试的**触发条件互斥**——令牌恢复仅对 `401` 生效，HTTP 重试对 `5xx`/异常生效（全局 `PollyResiliencePolicyProvider` 的重试谓词只处理异常与 `RetryStatusCodes`）。**无法构造同一请求同时命中两层重试的确定性场景**，强行构造将产生误导性/同义反复的测试。
- **改为锁定可独立观测的单层计数**（既有测试已覆盖，作为乘积上界的两因子）：
  - `TokenRecoveryDelegatingHandlerTests.SendAsync_WithMultipleRetries_RetriesConfiguredTimes` → `count == 1 + RecoveryMaxRetries`；
  - `Resilience.Tests`（`RetryStatusCodes` / `MaxRetryAttempts`）→ `count == 1 + MaxRetryAttempts`。
- **结论**：乘积 `(1+Rr)×(1+Hr)` 作为**文档契约**（ADR）存在，由上述两因子测试间接守护。

### 13.3 需修订的两处设计（已写入正文）

- **CFG-04（Prefix）**：原稿让 `TryGenerateInlineQueryFlattening` 复用 `separator` 拼 prefix，会产生 `filter,a`（`separator=","`）而非契约要求的 `filter.a`。**修订**：`GeneratePropertyFlatteningInline` 的 key 计算改为「前缀原样拼接」——`key = prefix + propName`，其中顶层前缀由 `Prefix` 与 `.` 组成、嵌套前缀为 `key + separator`；`GenerateIQueryParameterInline` 同步改为 `keyPrefix + kvp.Key`（调用方传已含尾部分隔符的前缀）。这样**未设置 Prefix 时生成结果逐字节不变**（回归安全）。
- **CFG-06（接线边界）**：`SensitiveDataMasker` / `JsonTypeInfoResolver` 直接接线；`RequestInterceptor` / `ResponseInterceptor` 需扩展 `DefaultHttpRequestExecutor`（新增可选 interceptors 形参，发送前后执行）+ `ConstructorGenerator`（生成形参）+ 生成工厂（传参）三处，已按未发布场景纳入本轮。
