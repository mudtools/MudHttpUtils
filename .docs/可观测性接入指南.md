## 1. 架构总览

Mud.HttpUtils 内置三大可观测性支柱的采集点，所有静态源位于 `Mud.HttpUtils.Abstractions` 项目，跨项目共享：

```
┌─────────────────────────────────────────────────────────────┐
│                  Mud.HttpUtils 应用层                        │
│   EnhancedHttpClient / ResilientHttpClient / TokenManager   │
└────┬──────────────────────────────┬─────────────────────────┘
     │                              │
     ▼                              ▼
┌──────────────────┐         ┌──────────────────┐
│  ActivitySource   │         │      Meter        │
│  Mud.HttpUtils.   │         │  Mud.HttpUtils.   │
│  HttpClient       │         │  HttpClient       │
└────┬─────────────┘         └────┬──────────────┘
     │                            │
     ▼                            ▼
┌──────────────────────────────────────────────────────────┐
│   Mud.HttpUtils.OpenTelemetry 适配包（可选）              │
│   AddMudHttpOpenTelemetry() 一键接入                      │
└────┬─────────────────────────────────────────────────────┘
     │
     ▼
┌──────────────────────────────────────────────────────────┐
│   OpenTelemetry SDK → OTLP Exporter → Jaeger/Prometheus  │
└──────────────────────────────────────────────────────────┘
```

### 三大静态源

| 类型 | 名称 | 位置 |
|------|------|------|
| `ActivitySource` | `Mud.HttpUtils.HttpClient` | `MudHttpActivitySource.cs` |
| `Meter` | `Mud.HttpUtils.HttpClient` v2.0.0 | `MudHttpMeter.cs` |
| `DiagnosticListener` | `Mud.HttpUtils.HttpClient` | `MudHttpDiagnosticListener.cs` |

> 即使不引用 OpenTelemetry 适配包，这些源也始终存在；只是默认无监听器，调用零开销。

## 2. 依赖包

### 最小依赖（仅可观测性内置采集）

```xml
<PackageReference Include="Mud.HttpUtils.Client" Version="2.0.0" />
```

无需额外引用 OpenTelemetry 包，所有 `ActivitySource` / `Meter` / `DiagnosticListener` 已在 `Mud.HttpUtils.Abstractions` 中静态初始化。

### 推荐：一键接入 OpenTelemetry

```xml
<PackageReference Include="Mud.HttpUtils.OpenTelemetry" Version="2.0.0" />
```

> 此包仅支持 `net8.0` / `net10.0`，因为 OpenTelemetry SDK 1.10.0 已不再支持 `net6.0`。

## 3. 一键开启 OpenTelemetry

### 3.1 ASP.NET Core 主机

```csharp
var builder = WebApplication.CreateBuilder(args);

// 1) 注册 Mud.HttpUtils 客户端
builder.Services.AddMudHttpClient("myApi", c =>
{
    c.BaseAddress = new Uri("https://api.example.com");
});

// 2) 一键开启 Mud.HttpUtils 的 OpenTelemetry 追踪与指标
builder.Services.AddMudHttpOpenTelemetry(options =>
{
    options.OtlpEndpoint = new Uri("http://otel-collector:4317");
});

// 3) 可选：注册健康检查
builder.Services.AddMudHttpHealthChecks();

var app = builder.Build();

// 4) 可选：暴露健康检查端点
app.MapHealthChecks("/health");

app.Run();
```

### 3.2 控制台应用

```csharp
var services = new ServiceCollection();
services.AddLogging();
services.AddMudHttpClient("myApi", c => c.BaseAddress = new Uri("https://api.example.com"));
services.AddMudHttpOpenTelemetry(options =>
{
    options.EnableAspNetCoreInstrumentation = false; // 控制台无入站请求
});

using var provider = services.BuildServiceProvider();
```

### 3.3 配置选项

| 属性 | 默认值 | 说明 |
|------|--------|------|
| `EnableTracing` | `true` | 启用分布式追踪 |
| `EnableMetrics` | `true` | 启用指标采集 |
| `EnableLogging` | `false` | 启用 OTLP 日志导出（向后兼容默认关闭，依赖 .NET 8+ ILogger 集成） |
| `EnableHttpClientInstrumentation` | `true` | 关联 .NET HttpClient 内置 ActivitySource |
| `EnableAspNetCoreInstrumentation` | `true` | 启用 ASP.NET Core 入站请求 Instrumentation |
| `ServiceName` | `Mud.HttpUtils.Application` | OTel Resource 的 `service.name` 属性 |
| `ServiceVersion` | `MudHttpActivitySource.Version` | OTel Resource 的 `service.version` 属性 |
| `DeploymentEnvironment` | `production` | OTel Resource 的 `deployment.environment` 属性 |
| `SamplingRatio` | `1.0` | 采样比率（0.0~1.0），使用 `ParentBasedSampler(TraceIdRatioBasedSampler)`。生产环境建议 0.1~0.3 |
| `OtlpEndpoint` | `http://localhost:4317` | OTLP 端点，`null` 跳过 OTLP 导出器 |
| `OtlpExportProtocol` | `Grpc` | OTLP 协议（`Grpc` / `HttpProtobuf`） |
| `OtlpHeaders` | `null` | 自定义 OTLP 认证头（如 `Authorization: Bearer <token>`），用于 OTLP Collector 鉴权 |
| `ExportBatchSize` | `null` | 批量导出大小（仅选项保留，需通过 `ConfigureTracing`/`ConfigureMetrics` 委托应用） |
| `ExportIntervalMilliseconds` | `null` | 批量导出间隔毫秒（仅选项保留，需通过 `ConfigureTracing`/`ConfigureMetrics` 委托应用） |
| `UseShortExporterTimeout` | `false` | 5 秒短超时（开发调试用） |
| `ConfigureTracing` | `null` | 自定义 `TracerProviderBuilder` 配置委托 |
| `ConfigureMetrics` | `null` | 自定义 `MeterProviderBuilder` 配置委托 |
| `ConfigureLogging` | `null` | 自定义 `LoggerProviderBuilder` 配置委托（仅在 `EnableLogging=true` 时生效） |

### 3.4 高级配置：追加 Prometheus 导出器

```csharp
// 需额外引用 OpenTelemetry.Exporter.Prometheus.AspNetCore
builder.Services.AddMudHttpOpenTelemetry(options =>
{
    options.OtlpEndpoint = null; // 关闭 OTLP
    options.ConfigureMetrics = mp =>
    {
        mp.AddPrometheusExporter();
    };
});

var app = builder.Build();
app.UseOpenTelemetryPrometheusScrapingEndpoint("/metrics");
```

## 4. 日志（Logs）

Mud.HttpUtils 使用 `LoggerMessage` 模式实现零分配日志：

- `MudHttpClientLog` / `ResilienceLogs` 采用 `[LoggerMessage]` 源生成器（.NET 6+）+ `LoggerMessage.Define`（netstandard2.0）双轨实现
- `EnhancedHttpClientLogs` 统一使用 `LoggerMessage.Define`（在所有目标框架上等价零分配）
- 所有日志 EventId 集中在 `MudHttpClientLog` / `EnhancedHttpClientLogs` / `ResilienceLogs` 等部分类
- 自动包含 `CorrelationId` 日志作用域，便于关联同一请求的多条日志

### 关键 EventId

| EventId | 名称 | 来源 |
|---------|------|------|
| 100 | `RetryAttempting` | `PollyResiliencePolicyProvider` |
| 101 | `RetryCallbackFailed` | 同上 |
| 102 | `CircuitBreakerOpenedSimple` | 同上 |
| 103 | `CircuitBreakerOpenedAdvanced` | 同上 |
| 104 | `CircuitBreakerClosed` | 同上 |
| 105 | `CircuitBreakerHalfOpen` | 同上 |
| 106 | `RequestTimeout` | 同上 |
| 200-299 | 各类请求/响应日志 | `EnhancedHttpClientLogs` |
| 300-399 | 令牌刷新日志 | `TokenRefreshBackgroundService` |

### 启用 CorrelationId 作用域

```csharp
builder.Services.AddMudHttpClient("myApi", c => c.BaseAddress = new Uri("https://api.example.com"));
// CorrelationId 自动通过 Activity.Current?.TraceId 或 Guid 派生，无需额外配置
```

## 5. 指标（Metrics）参考

所有指标由 `MudHttpMeter`（名称 `Mud.HttpUtils.HttpClient`，版本 `2.0.0`）导出，遵循 [OpenTelemetry HTTP 语义约定](https://opentelemetry.io/docs/specs/semconv/http/http-metrics/)。

### 5.1 指标列表

| 指标名 | 类型 | 单位 | 维度 | 说明 |
|--------|------|------|------|------|
| `mud.http.requests` | Counter | `{request}` | client_name, method, host, status_code, outcome | HTTP 请求总数 |
| `mud.http.request.duration` | Histogram | `ms` | client_name, method, host, status_code | HTTP 请求耗时分布 |
| `mud.http.cache` | Counter | `{operation}` | client_name, outcome, cache_key | 缓存命中/未命中计数 |
| `mud.token.refresh` | Counter | `{operation}` | token_manager_key, outcome | 令牌刷新次数 |
| `mud.token.refresh.duration` | Histogram | `ms` | token_manager_key | 令牌刷新耗时分布 |
| `mud.token.recovery` | Counter | `{operation}` | token_manager_key, outcome | 令牌恢复（401 重试）次数与结果 |
| `mud.http.retry` | Counter | `{retry}` | policy_key, outcome, retry_count | 重试次数 |
| `mud.http.circuit_breaker.state` | ObservableGauge | `{state}` | policy_key | 熔断器当前状态（0=Closed, 1=HalfOpen, 2=Open） |

### 5.2 维度语义

- `outcome`：
  - HTTP 请求：`success` / `redirect` / `client_error` / `server_error` / `unknown` / `error`
  - 缓存：`hit` / `miss`
  - 令牌刷新：`success` / `failure` / `fallback`
  - 重试：`retry` / `timeout`
- `client_name`：Named HttpClient 名称（来自 `IHttpClientFactory`）
- `policy_key`：弹性策略键，如 `global:retry` / `global:circuitBreaker` / `method:R=true:3:...`

> **注意**：`redirect`（3xx）与 `unknown`（无法解析状态码）为 v3 补充的枚举值，原文档仅列出 `success` / `client_error` / `server_error` / `error`。`error` 仅在请求抛出异常（未获得响应）时使用。

### 5.3 Prometheus 抓取示例

抓取到的时间序列示例：

```
mud_http_requests_total{client_name="myApi",method="GET",host="api.example.com",status_code="200",outcome="success"} 1234
mud_http_request_duration_ms_bucket{client_name="myApi",method="GET",host="api.example.com",status_code="200",le="100"} 1100
mud_http_cache_total{outcome="hit",cache_key="user_1"} 56
mud_token_refresh_total{token_manager_key="feishu",outcome="success"} 8
mud_http_retry_total{policy_key="global:retry",outcome="retry",retry_count="1"} 23
mud_http_circuit_breaker_state{policy_key="global:circuitBreaker"} 0
```

### 5.4 Grafana 常用 PromQL

```promql
# HTTP 请求 QPS
sum(rate(mud_http_requests_total[1m])) by (client_name)

# P99 请求耗时
histogram_quantile(0.99, sum(rate(mud_http_request_duration_ms_bucket[5m])) by (le, client_name))

# 缓存命中率
sum(rate(mud_http_cache_total{outcome="hit"}[5m])) by (cache_key)
  /
sum(rate(mud_http_cache_total[5m])) by (cache_key)

# 令牌刷新失败率
sum(rate(mud_token_refresh_total{outcome="failure"}[5m])) by (token_manager_key)
  /
sum(rate(mud_token_refresh_total[5m])) by (token_manager_key)

# 熔断器开启时长占比
avg_over_time(mud_http_circuit_breaker_state[10m]) == 2
```

## 6. 追踪（Traces）参考

### 6.1 Span 属性（OTel 语义约定）

| 属性 | 来源 | 示例 |
|------|------|------|
| `http.method` | OTel 标准 | `GET` |
| `http.url` | OTel 标准 | `https://api.example.com/users/1` |
| `http.host` | OTel 标准 | `api.example.com` |
| `http.scheme` | OTel 标准 | `https` |
| `http.status_code` | OTel 标准 | `200` |
| `http.response_content_length` | OTel 标准 | `1024` |
| `http.response.status_code_class` | **Mud 自定义**（非 OTel 标准） | `2xx` |
| `mud.http.client_name` | Mud 自定义 | `myApi` |
| `mud.http.retry.count` | Mud 自定义 | `2` |
| `mud.http.cache.hit` | Mud 自定义 | `true` |
| `mud.token.manager_key` | Mud 自定义 | `feishu` |
| `mud.http.circuit_breaker.state` | Mud 自定义 | `Open` |
| `mud.correlation_id` | Mud 自定义 | `0a1b2c3d...` |

> **注意**：`http.response.status_code_class` 为 Mud 自定义扩展属性，不在 OTel HTTP 语义约定中。它将状态码按百位分类（`1xx`/`2xx`/`3xx`/`4xx`/`5xx`/`0xx`），便于在 Jaeger 中按状态码类别过滤。

> **Span Status 规范**：遵循 [OTel HTTP 客户端 span 规范](https://opentelemetry.io/docs/specs/semconv/http/http-spans/#status)，仅 5xx 与网络异常设为 `Error`，4xx 设为 `OK`（客户端正常业务流，如 401 触发令牌恢复、404 资源不存在）。

### 6.2 Span 事件

| 事件名 | 触发时机 | 负载 |
|--------|----------|------|
| `RequestStarted` | HTTP 请求发出前 | method, url, client_name |
| `RequestStopped` | 收到响应后 | method, url, client_name, status_code, elapsed_ms |
| `RequestFailed` | 请求异常时 | method, url, client_name, elapsed_ms, exception |
| `RetryOccurred` | Polly 重试回调 | policy_key, retry_count, delay_ms, exception_type |
| `TimeoutOccurred` | Polly 超时回调 | policy_key, timeout_ms |
| `CircuitBreakerStateChanged` | 熔断器状态变化 | policy_key, new_state |
| `TokenRefreshed` | 令牌刷新完成 | token_manager_key, success, elapsed_ms, is_fallback |
| `CacheHit` / `CacheMiss` | 缓存命中/未命中 | cache_key, hit |
| `exception` | 请求异常时（.NET 8+） | exception.type, exception.message, exception.stacktrace |

> **双路径一致性**：所有 Span 事件在两条采集路径下均产出：
> - **路径 A**：`IHttpClientFactory` + `TracingDelegatingHandler`（推荐 DI 场景）
> - **路径 B**：直接 `new EnhancedHttpClient(new HttpClient(), ...)`（控制台/测试场景）
>
> 两条路径通过 `__mud_observed` 标记去重，不会重复写入。`exception` 事件在 .NET 8+ 上遵循 [OTel Span Exceptions 规范](https://opentelemetry.io/docs/specs/semconv/exceptions/exceptions-spans/) 以 ActivityEvent 形式记录；netstandard2.0/net6.0 降级为 `exception.*` tag。

### 6.3 Jaeger 中查看 Span

```
[mud.http.client_request] GET https://api.example.com/users/1
  ├─ http.method = GET
  ├─ http.url = https://api.example.com/users/1
  ├─ mud.http.client_name = myApi
  ├─ mud.http.retry.count = 2
  ├─ Event: RequestStarted
  ├─ Event: RetryOccurred (retry_count=1, delay_ms=200)
  ├─ Event: RetryOccurred (retry_count=2, delay_ms=400)
  ├─ Event: RequestStopped (status_code=200, elapsed_ms=1234.5)
  └─ http.status_code = 200
```

### 6.4 Token Recovery 子 Span

当 `TokenRecoveryDelegatingHandler` 收到 401 Unauthorized 并触发令牌刷新重试时，会创建子 Span `Mud.HttpUtils.Token.Recovery`：

```
[mud.http.client_request] GET https://api.example.com/users/1
  └─ [Mud.HttpUtils.Token.Recovery]
       ├─ mud.token.manager_key = StandardOAuth2TokenManager
       ├─ mud.token.recovery.success = true
       ├─ mud.token.recovery.elapsed_ms = 152.3
       └─ http.status_code = 200
```

- `mud.token.recovery.success`：恢复是否成功（重试后获得非 401 响应）
- `mud.token.recovery.elapsed_ms`：恢复总耗时（含令牌刷新 + 重试请求）
- 恢复失败（重试耗尽仍为 401）时 Span 状态为 `Error`
- 同时记录 `mud.token.recovery` Counter 指标（维度：token_manager_key, outcome）

## 7. 健康检查（Health Checks）

### 7.1 注册

```csharp
builder.Services.AddMudHttpHealthChecks();
// 或基于配置
builder.Services.AddMudHttpHealthChecks(builder.Configuration);
```

### 7.2 暴露端点

```csharp
app.MapHealthChecks("/health");
```

### 7.3 检查项

| 名称 | 类型 | 判定逻辑 |
|------|------|----------|
| `mud_token_refresh` | `TokenRefreshHealthCheck` | 5 分钟窗口内失败率 ≥ `CriticalThreshold`（默认 0.5）→ Unhealthy；≥ `DegradedThreshold`（默认 0.2）→ Degraded；样本 < `MinSampleSize`（默认 5）→ Healthy |
| `mud_circuit_breaker` | `MudCircuitBreakerHealthCheck` | Open 计数 > `MaxOpenCount`（默认 0）→ Unhealthy；HalfOpen > `MaxHalfOpenCount`（默认 0）→ Degraded |

> 默认阈值为最严格值（任何 Open 即 Unhealthy），可通过配置放宽。

### 7.4 配置阈值

```json
{
  "MudHttpHealthChecks": {
    "TokenRefresh": {
      "WindowSeconds": 300,
      "DegradedThreshold": 0.2,
      "CriticalThreshold": 0.5,
      "MinSampleSize": 5
    },
    "CircuitBreaker": {
      "MaxOpenCount": 1,
      "MaxHalfOpenCount": 1
    }
  }
}
```

### 7.5 自定义健康检查响应

```csharp
app.MapHealthChecks("/health", new HealthCheckOptions
{
    ResponseWriter = async (context, report) =>
    {
        context.Response.ContentType = "application/json";
        var result = JsonSerializer.Serialize(new
        {
            status = report.Status.ToString(),
            checks = report.Entries.Select(e => new
            {
                name = e.Key,
                status = e.Value.Status.ToString(),
                description = e.Value.Description,
                data = e.Value.Data
            })
        });
        await context.Response.WriteAsync(result);
    }
});
```

## 8. DiagnosticSource 事件订阅

Mud.HttpUtils 通过 `MudHttpDiagnosticListener` 单例写入事件，外部 APM 探针或自定义订阅器可订阅：

### 8.1 事件名称常量

| 常量 | 值 |
|------|----|
| `MudHttpDiagnosticNames.ListenerName` | `Mud.HttpUtils.HttpClient` |
| `MudHttpDiagnosticNames.RequestStarted` | `RequestStarted` |
| `MudHttpDiagnosticNames.RequestStopped` | `RequestStopped` |
| `MudHttpDiagnosticNames.RequestFailed` | `RequestFailed` |
| `MudHttpDiagnosticNames.RetryOccurred` | `RetryOccurred` |
| `MudHttpDiagnosticNames.CircuitBreakerStateChanged` | `CircuitBreakerStateChanged` |
| `MudHttpDiagnosticNames.TokenRefreshed` | `TokenRefreshed` |
| `MudHttpDiagnosticNames.CacheHit` | `CacheHit` |
| `MudHttpDiagnosticNames.CacheMiss` | `CacheMiss` |

### 8.2 订阅示例

```csharp
public sealed class MudHttpDiagnosticSubscriber : IObserver<DiagnosticListener>
{
    public void OnNext(DiagnosticListener listener)
    {
        if (listener.Name == MudHttpDiagnosticNames.ListenerName)
        {
            listener.Subscribe(new MudHttpEventListener());
        }
    }

    public void OnCompleted() { }
    public void OnError(Exception error) { }
}

public sealed class MudHttpEventListener : IObserver<KeyValuePair<string, object?>>
{
    public void OnNext(KeyValuePair<string, object?> value)
    {
        switch (value.Key)
        {
            case MudHttpDiagnosticNames.RetryOccurred:
                if (value.Value is RetryDiagnosticPayload retry)
                {
                    Console.WriteLine($"[Retry] policy={retry.PolicyKey} count={retry.RetryCount} delay={retry.DelayMs}ms");
                }
                break;
            case MudHttpDiagnosticNames.CircuitBreakerStateChanged:
                if (value.Value is CircuitBreakerDiagnosticPayload cb)
                {
                    Console.WriteLine($"[CircuitBreaker] policy={cb.PolicyKey} state={cb.State}");
                }
                break;
        }
    }

    public void OnCompleted() { }
    public void OnError(Exception error) { }
}

// 在应用启动时订阅
DiagnosticListener.AllListeners.Subscribe(new MudHttpDiagnosticSubscriber());
```

## 9. 部署示例：Jaeger + Prometheus + Grafana

### 9.1 docker-compose.yml

```yaml
version: '3.8'

services:
  jaeger:
    image: jaegertracing/all-in-one:1.62
    ports:
      - "16686:16686"  # Jaeger UI
      - "4317:4317"    # OTLP gRPC
      - "4318:4318"    # OTLP HTTP

  otel-collector:
    image: otel/opentelemetry-collector-contrib:0.110.0
    command: ["--config=/etc/otel-collector-config.yaml"]
    volumes:
      - ./otel-collector-config.yaml:/etc/otel-collector-config.yaml
    ports:
      - "8889:8889"    # Prometheus exposition

  prometheus:
    image: prom/prometheus:v2.55.0
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
    ports:
      - "9090:9090"

  grafana:
    image: grafana/grafana:11.3.0
    ports:
      - "3000:3000"
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=admin
```

```yaml
receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317

      insecure: true

    endpoint: 0.0.0.0:8889

      receivers: [otlp]

      receivers: [otlp]
      exporters: [prometheus]
```

```yaml
scrape_configs:
  - job_name: 'otel-collector'
    scrape_interval: 15s
    static_configs:
      - targets: ['otel-collector:8889']
```

```bash
docker-compose up -d
```

- Jaeger UI: http://localhost:16686
- Prometheus: http://localhost:9090
- Grafana: http://localhost:3000（admin/admin，添加 Prometheus 数据源 http://prometheus:9090）

## 10. 常见问题

### 10.1 不引用 OpenTelemetry 适配包能采集到指标吗？

可以。`MudHttpMeter` / `MudHttpActivitySource` / `MudHttpDiagnosticListener` 始终存在并写入数据，但默认无监听器。需自行通过 `MeterListener` / `ActivityListener` / `DiagnosticListener.AllListeners` 订阅，或引用 `Mud.HttpUtils.OpenTelemetry` 包通过 OTel SDK 自动订阅。

### 10.2 启用 OTel 后性能影响多大？

- 无监听器时：`ActivitySource.StartActivity` 返回 `null`，`Counter.Add` 内联短路，开销 < 10ns
- 有监听器时：每次请求产生 1 个 Activity + 几次 Counter.Add + 1-2 个 DiagnosticSource 事件，总开销约 5-20μs
- 建议生产环境始终通过 OTel 采集，由 Collector 决定是否丢弃

### 10.3 如何禁用某个维度的采集？

```csharp
services.AddMudHttpOpenTelemetry(options =>
{
    options.EnableTracing = false;  // 关闭追踪
    // 或
    options.EnableMetrics = false;  // 关闭指标
});
```

### 10.4 如何自定义 OTLP 端点（如通过环境变量）？

```csharp
builder.Services.AddMudHttpOpenTelemetry(options =>
{
    var endpoint = Environment.GetEnvironmentVariable("OTEL_EXPORTER_OTLP_ENDPOINT");
    if (!string.IsNullOrEmpty(endpoint))
    {
        options.OtlpEndpoint = new Uri(endpoint);
    }
});
```

### 10.5 如何在 net6.0 / netstandard2.0 项目中使用？

`Mud.HttpUtils.OpenTelemetry` 适配包仅支持 `net8.0+`。低版本项目请：

1. 直接引用 `OpenTelemetry.*` 1.9.0 或更低版本
2. 在 `Program.cs` 中手动调用：
   ```csharp
   services.AddOpenTelemetry()
       .WithTracing(tp => tp
           .AddSource(MudHttpActivitySource.Name)
           .AddHttpClientInstrumentation()
           .AddOtlpExporter())
       .WithMetrics(mp => mp
           .AddMeter(MudHttpMeter.MeterName)
           .AddHttpClientInstrumentation()
           .AddOtlpExporter());
   ```

### 10.6 为什么重试 span 没有出现在 Jaeger？

Mud.HttpUtils 的 ActivitySource 只创建一个出站请求 span，重试事件以 **Span Event** 形式记录在该 span 上。在 Jaeger UI 中展开 span 详情可见 `RetryOccurred` 事件。

### 10.7 如何在测试中验证 OTel 集成？

参考 `Tests/Mud.HttpUtils.OpenTelemetry.Tests/MudHttpOpenTelemetryExtensionsTests.cs`，通过 `IServiceProvider.GetService<MeterProvider>()` / `TracerProvider` 验证服务注册。也可通过 `MeterListener` 捕获测量事件做断言。

### 10.8 健康检查 `mud_token_refresh` 总是 Healthy？

健康检查依赖 `TokenRefreshStatsCollector` 的统计数据。如果应用从未触发令牌刷新，统计为空，`MinSampleSize` 检查会返回 Healthy。手动触发几次刷新（成功 + 失败混合）后再观察。

### 10.9 如何配置采样率？

通过 `SamplingRatio` 选项配置，底层使用 `ParentBasedSampler(TraceIdRatioBasedSampler)`（继承父采样决策 + 按比率采样根 span）：

```csharp
builder.Services.AddMudHttpOpenTelemetry(options =>
{
    options.SamplingRatio = 0.1; // 10% 采样
});
```

- `1.0`（默认）：全采样，适合开发调试
- `0.1~0.3`：生产环境推荐范围
- `0.0`：不采样（不推荐，会丢失所有追踪数据）
- 父 span 被采样时，子 span 总是被采样（ParentBased 语义）

### 10.10 如何启用 OTLP 日志导出？

通过 `EnableLogging = true` 启用，结构化日志（`LoggerMessage` 模式）将通过 OTLP 导出至 Loki/Tempo 等日志后端：

```csharp
builder.Services.AddMudHttpOpenTelemetry(options =>
{
    options.EnableLogging = true;
    options.OtlpEndpoint = new Uri("http://otel-collector:4317");
});
```

> 日志导出依赖 .NET 8+ 的 `ILogger` 集成，仅在 net8.0/net10.0 上可用。net6.0/netstandard2.0 请手动配置 OTel Logs SDK。

### 10.11 如何配置 OTLP Collector 认证头？

通过 `OtlpHeaders` 选项添加自定义认证头：

```csharp
builder.Services.AddMudHttpOpenTelemetry(options =>
{
    options.OtlpEndpoint = new Uri("https://otel-collector.internal:4317");
    options.OtlpHeaders = new Dictionary<string, string>
    {
        { "Authorization", "Bearer <collector-token>" },
        { "X-API-Key", "<api-key>" }
    };
});
```

Headers 会同时应用到 Traces、Metrics、Logs 三个导出器。
