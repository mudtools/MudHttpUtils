## 四、技术实现

### 4.1 清理脚本

**文件**：`scripts/cleanup-dev-codes.py`

**核心功能**：
- 递归扫描 `.cs` 文件
- 匹配 8 种开发代号模式
- 保留注释结构（`//` / `///`）
- 支持 dry-run 预览模式

**关键正则表达式**：
```python
DEV_CODE_PATTERNS = [
    r'G\d+-\d+[：:\s]',              # G7-03：
    r'M\d+-[A-Z]+-\d+[：:/\s\(]',   # M6-HC-12：
    r'(EL|TK|HC)-\d+\s*修复[：:\s]', # HC-04 修复：
    r'[GM]\d+[-\w]+\s*[（(][^）)]+[）)]\s*[：:\s]',  # M6-HC-05（D2-A）：
    r'[GM]\d+-\d+[a-z]*/',          # G8-01/
    r'（评审修订\s*\d+）',           # （评审修订 7）
]
```

### 4.2 验证工具

**文件**：`scripts/lint-comments.py`

**功能**：
- 扫描违规注释模式
- 输出详细违规位置
- 返回非零退出码供 CI 使用

## 七、经验总结

### 7.1 成功经验

1. **自动化优先**：通过正则匹配批量清理，效率提升 10 倍以上
2. **分轮次迭代**：每轮针对特定模式优化，避免一次性复杂度过高
3. **dry-run 验证**：先预览再应用，降低误删风险
4. **保留核心技术说明**：只移除追踪号，不删除有价值的技术解释

### 7.2 改进空间

1. **正则覆盖率**：首次实现遗漏了 15% 的边缘格式，需多轮迭代
2. **中文标点处理**：全角/半角冒号、括号的混合使用增加了匹配难度
3. **上下文感知**：无法判断某个标记是否"仍在进行中"，需要人工介入

### 7.3 最佳实践

> **注释清理黄金法则**：
> - 清理的是"追踪号"，不是"技术说明"
> - 保留"为什么这样做"，删除"谁在什么时候决定的"
> - 复杂决策迁移至 ADR，代码中只留引用
