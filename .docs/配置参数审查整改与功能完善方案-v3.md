### 1.3 最重要的两项结论（先读）

> **结论 A —— 本轮 High 之一（CFG-28）是上一轮修复引入的「回归」，不是遗留问题。**
> `.docs/README.md`「独立复核补记（2026-09-13）⑥」记载：上一轮为修复 `[Retry(3, 1000)]` 绑定失败，
> **新增了 `RetryAttribute(int maxRetries, int delayMilliseconds)` 双参构造函数**。
> 但生成器侧 `AnalyzeRetryAttribute` **只读取命名参数**，从未读取 `ConstructorArguments[1]`——
> 即新构造函数的位置参数 `delayMilliseconds` **从诞生之日起就是死配置**。
> 现有快照测试恰好使用 `[Retry(3, 1000)]`（1000 等于默认值），因此**永远无法暴露该缺陷**。

> **结论 B —— 特性（Attribute）的值域校验必须在生成器分析阶段完成，写在 setter 中完全无效。**
> Roslyn **从不实例化** Attribute（特性以元数据形式存在于编译产物中，生成器读到的是 `AttributeData`），
> 因此 `CircuitBreakerAttribute.FailureThreshold { set => if (...) throw ...; }` 这类写法
> **在任何编译路径下都不会执行**。这与 `CircuitBreakerOptions`（运行时由 `IConfiguration`/委托实例化，setter 会执行）
> 形成**根本性差异**，是本轮 CFG-29 / CFG-32 的方案分水岭，也是第 2 轮「选项侧已加 setter 校验」却仍留缺口的原因。
> **实施纪律**：① 类别（特性参数）的问题**一律**用生成器诊断解决，禁止靠在 Attribute setter 里抛异常。

### 1.4 目标与非目标

**目标**

1. **消除静默失效**：`已配置但被忽略的取值` 必须由「编译期诊断 / 启动期校验失败 / 启动期警告日志」三者之一兜住（延续 v2 §3.1「不静默原则」）。
2. **特性参数读取口径统一**：位置参数与命名参数的取值优先级遵循 **C# 特性赋值语义**（命名参数后赋值 ⇒ 优先），并建立**机器守卫**防止「特性加属性、生成器忘了读」再次发生（对应功能完善 F-1）。
3. **跨路径语义对齐**：DI 路径与无 DI 路径的同名/同语义配置项必须**语义一致或显式声明差异**。
4. **文档即契约**：区分「文档滞后于代码」与「代码未实现文档承诺」，后者优先修复。
5. **可回归**：每条 `CFG-nn` 提供可执行的最小验证用例。

**非目标**

- ❌ 不重构请求执行编排、缓存实现、SSRF 策略实现等无关链路。
- ❌ 不引入新第三方依赖。
- ❌ 不处理 v2 遗留的 `BC-5`（`TokenRefreshBackgroundOptions.SectionName` 改名，推迟至大版本）。
- ❌ 不实施 `03-P2` Roadmap `R-3`（`IUrlValidator` 实例化 + DI）—— 本方案 CFG-34 采用其**前置的轻量方案**，`R-3` 仍留待后续。
- ❌ 不新增端点级弹性策略（`R-4`）。

### CFG-28：`[Retry(maxRetries, delayMilliseconds)]` 位置参数被丢弃（**High，含回归**）

- **类型**：从未生效（特性参数）；RN-1
- **证据链**：
  - 定义：`Mud.HttpUtils.Attributes/RetryAttribute.cs:24-28`（双参构造函数体赋值）、`:34`（`DelayMilliseconds { get; set; } = 1000`）

### CFG-30：`HttpVersion` 默认值跨路径不一致（复核后：Low；撤销「覆盖 `HttpClient` 设置」的定性）

- **类型**：跨路径**声明**不一致（**非**功能冲突）；RN-3

> **❌ 复核结论（v3.1）：原方案的核心前提不成立。**
> `HttpClient.DefaultRequestVersion` **不适用于 `SendAsync`**。MS 官方文档原文：
> 「The DefaultRequestVersion property doesn't apply to the SendAsync method. The HttpRequestMessage parameter passed as
> the argument to the SendAsync method has its own Version property that controls the HTTP version used for the request.」
> runtime 源码 `System.Net.Http/HttpClient.cs` 亦证实：该值只被内部 `CreateRequestMessage` 消费（即 `GetAsync`/`PostAsync`/… 便捷重载）。
> 本库两条路径（`EnhancedHttpClient.ApplyRequestConfig` / `DefaultHttpRequestExecutor.ApplyRequestConfig`）**均自建 `HttpRequestMessage` 并调用 `SendAsync`**，
> 故 `HttpClient.DefaultRequestVersion` 对二者**都不生效** —— 既不存在「DI 路径覆盖了它」，也不存在「无 DI 路径保留了它」。
> 更关键：`EnhancedHttpClientOptions` 的原默认组合（`Version11` + `RequestVersionOrLower`）与 `HttpRequestMessage` 的构造默认值**完全一致**
> （`HttpRequestMessage.Version` 默认 1.1、`VersionPolicy` 默认 `RequestVersionOrLower`），因此**改为 `null` 不产生任何可观察行为差异**。
> **连带修正**：原 `BC-8`（登记为「行为变更」）**撤销**；原用例 `T6`（断言 `DefaultRequestVersion=2.0` 生效）**不可能通过**，已重写为
> 「未配置时不干预 `HttpRequestMessage.Version`（保持 1.1）」+「文档明确 `DefaultRequestVersion` 不适用于本库路径」。
> **仍保留的动作（降级为一致性清理）**：默认值对齐为 `null`（与 `GeneratedClientOptions` 一致，消除「声明层漂移」），
> 并在 `Client/README.md` 增补「本库经 `SendAsync` 发送，`HttpClient.DefaultRequestVersion` 不生效；如需 HTTP/2/3 请配置 `HttpVersion`」。
- **证据链**：
  - 定义：`EnhancedHttpClientOptions.cs:131`（`= System.Net.HttpVersion.Version11`）；`GeneratedClientOptions.cs:155`（`= null`）；共享契约 `IEnhancedClientConfig.cs:52`
  - 绑定/构造：`ServiceCollectionExtensions.cs:764-765` 克隆 `IOptions<EnhancedHttpClientOptions>.Value`（**即使调用方从未 `Configure<EnhancedHttpClientOptions>`，`IOptions<T>` 仍解析出全默认实例**）
  - 生效：`EnhancedHttpClient.cs:1871-1872` `if (_httpVersion != null) request.Version = _httpVersion;` ↔ `DefaultHttpRequestExecutor.cs:840-841`（`null` 时跳过）
  - 文档：`Client/README.md:59` 标注默认 `HttpVersion.Version11`，**未提示副作用**
- **根因**：RN-3。
- **方案选型**：
  - **方案 A（推荐）**：`EnhancedHttpClientOptions.HttpVersion` / `HttpVersionPolicy` 默认改为 `null`，与 `GeneratedClientOptions`、与 `HttpClient.DefaultRequestVersion` 三方语义对齐（「未配置即不干预」）。
    - 影响面：仅 `#if NET6_0_OR_GREATER`（`EnhancedHttpClientOptions.cs:126-138`）；netstandard2.0 下 `ApplyRequestConfig` 无该分支，不受影响。
    - 需核对 `RefitRefactorFeatureTests.cs:270-280`（该测试**已注释跳过** `HttpVersion` 断言 → 修复后补上）、`EnhancedHttpClientSubclassTests`、`M3P2FixTests.cs:34`（显式传 `httpVersion` 的用例不受影响）。
  - 方案 B（可选，若确认「显式钉 1.1」是设计意图）：保留默认值，但在 `EnhancedHttpClient.ApplyRequestConfig` 检测「`_httpVersion` 为默认实例来源 且 `HttpClient.DefaultRequestVersion != 1.1`」时记 `Debug`，并在 `EnhancedHttpClientOptions.cs:127-131` 与 `Client/README.md:59` 明示「会覆盖 `DefaultRequestVersion`」。
  - 方案 C（不推荐）：删除属性 → 公开 API 破坏，且无 DI 路径仍需要它。
- **裁决建议（v3.1 修订）**：**采用方案 A（默认改 `null`）**，定性为「**声明一致性清理**」而非行为变更，**不再登记 `BC-8`**（§8 已标注撤销）。
  方案 B（保留默认 + 记日志）**作废** —— 其触发条件「`_httpVersion` 来自默认实例且 `HttpClient.DefaultRequestVersion != 1.1`」所描述的场景本身不存在。
- **破坏性**：**无**（两条路径的可观察行为逐位相同，见上复核注）。
- **验收**：不变量 I-14（重写后语义）；用例 T6（重写，见 §9.2）。

### CFG-37：~~`TokenRefreshBackgroundOptions` 使用 `Bind` 缺变更令牌源~~（**已撤销**）
