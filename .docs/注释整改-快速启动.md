### 阶段二：批量清理类别 A（第 2-5 天）

#### 2.1 识别已完成的历史追踪

```bash
# 提取所有 G/M/P 系列标记
grep -rn "// \(G\|M\|P\)[0-9]" --include="*.cs" . > /tmp/all-markers.txt

ls .docs/*方案.md | grep -E "(0[1-9]|P0|P1)"
```

#### 2.2 自动化清理脚本

创建 `scripts/cleanup-category-a.py`：

```python
#!/usr/bin/env python3
"""
批量清理类别 A 注释（已完成的历史追踪）

用法：
    python scripts/cleanup-category-a.py --dry-run   # 预览变更
    python scripts/cleanup-category-a.py --apply     # 实际执行
"""

import re
import sys
from pathlib import Path

# 类别 A 特征：关联的方案文档已归档
CATEGORY_A_PATTERNS = [
    r'//\s*G7-\d+:',      # 生成器缺陷（已修复）
    r'//\s*M5-HC-\d+',    # M5 里程碑（已归档）
    r'//\s*M6-HC-\d+',    # M6 里程碑（已归档）
]

def is_category_a(comment: str) -> bool:
    """判断是否为类别 A（可安全清理）"""
    return any(re.search(p, comment) for p in CATEGORY_A_PATTERNS)

def simplify_comment(line: str) -> str:
    """简化注释：移除开发代号前缀"""
    # 示例：
    # "G7-03：半写防护——先写同目录临时文件..."
    # → "原子落盘：先写入 .mudtmp..."
    return re.sub(r'^//\s*[A-Z0-9-]+：', '// ', line)

def process_file(filepath: Path, dry_run: bool = True):
    """处理单个文件"""
    with open(filepath, 'r', encoding='utf-8') as f:
        lines = f.readlines()

    changes = []
    for i, line in enumerate(lines):
        if is_category_a(line.strip()):
            new_line = simplify_comment(line)
            changes.append((i + 1, line.rstrip(), new_line.rstrip()))

    if not changes:
        return

    print(f"\n📄 {filepath}:")
    for line_no, old, new in changes:
        if dry_run:
            print(f"  第 {line_no} 行:")
            print(f"    - {old}")
            print(f"    + {new}")
        else:
            # 实际替换逻辑（需完善）
            pass

if __name__ == '__main__':
    dry_run = '--dry-run' in sys.argv
    # 遍历目标文件...
```


## 常见问题

### Q1: 如何判断某个标记是"进行中"还是"已完成"？

**A**: 检查对应的 `.docs` 方案文档：
- 文档标题含"已完成"、"已归档" → 类别 A（清理）
- 文档状态为"进行中"且关联 P0/P1 Issue → 类别 C（保留）
- 不确定时 → 归类为类别 B（迁移至 ADR）

### Q2: ADR 文档应该多详细？

**A**: 遵循"够用即可"原则：
- 背景：2-3 段话说明问题
- 备选方案：每个方案 1 段描述 + 优缺点列表
- 决策：1-2 段核心理由
- 总长度控制在 500-800 字

### Q3: 清理过程中误删重要上下文怎么办？

**A**: 
1. 通过 git 历史恢复：`git log -p -- <file>`
2. 补充至 ADR 文档的"参考"章节
3. 在代码注释中添加 ADR 引用

### Q4: 如何处理第三方库的注释？

**A**: 
- 外部依赖的代码（如 `obj/` 目录）**不扫描**
- 仅关注本项目源代码（`Mud.HttpUtils.*` 目录）
