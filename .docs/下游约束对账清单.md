## C 系列：`MudFeishu` 侧约束

| # | 约束 | 状态 | 说明 |

| C-1 | `InvalidateTokenAsync` 级联清 store（memory + store 双清，TMA-01；`PurgeStoreOnTokenInvalidation` 默认 true） | **仍有效** | 与 B-2 自动桥接正交：桥接器 `TryRemove`/`Set(key, null)` 同步写穿删除（登出漏删防护 C6），级联清语义不变。 |
| C-2 | store 值必须含过期戳 `{expireTimestampMs}\|{token}`（`TokenStoreHelper.EncodeStoredToken`；无过期视同 miss，TMA-15） | **已裁决（2026-10-14）**：官方形态为相对秒；飞书迁移走双读 codec | 裁决：**官方 codec 形态锁定 `{expiresInSeconds}\|{token}`（相对秒）**——绝对毫秒戳在持久层滞留会被误判有效（时钟回拨/长期留存），官方不提供绝对戳变体。飞书现有形态是私有发明，迁移官方包时须实现自定义 `ITokenStoreCodec`（自定义 codec 是官方支持的扩展点，非逃生）：**Decode 双读兼容**（检测数值量级区分旧绝对毫秒戳/新相对秒，旧值按 `expiresAtMs - now` 换算剩余秒），**Encode 单写相对秒**；读写分离保证迁移期不混写同一键。旧数据无需回灌，按条目自然过期收敛（最长一个令牌 TTL 周期）。「无过期视同 miss」语义官方等价（`Decode` 非法格式返回 null → miss），TMA-15 口径不变。 |
| C-3 | 令牌键只允许由 `TokenKeyBuilder` 构造（D8，禁内联拼接） | **已失效**（官方上收） | F-2 `TokenScopeKey` 为官方键契约；飞书 `TokenKeyBuilder` 可改为薄包装委托官方（保持 D8 单一来源语义），内联拼接禁令继续有效。 |
| C-4 | `IFeishuTokenStoreFactory` per-appKey store 工厂 + `IFeishuUserTokenStorePurge` 用户级清库能力探测 | **仍有效** | 组件 `ITokenStore` 是单命名空间契约（appKey 维度在键内：`{prefix}:{tokenType}:{appKey}`），与飞书 per-appKey store 实例模型不同构。多应用隔离经键内 appKey 段表达，per-appKey factory 是飞书自身的装配选择，不受影响。 |
| C-5 | 恢复阈值 = 缓存有效性阈值同源（D9，禁第二套阈值） | **仍有效** | 与组件变更无关。 |

| C-7 | `FeishuAppContext` 退役队列 + Dispose 纪律（TMA-07/24） | **仍有效** | 与组件变更无关。 |

## 回收动作汇总（F-6-3，裁决版 2026-10-14）

1. **`WechatAppManager` 继承路径**（A-2，**已裁决：认可、择期迁移**）：改 `DefaultAppManager<IWechatAppContext>` 派生 + `IAppRegistry` 注入；三步门槛（合规套件取证 → 特有语义覆写保真 → 42001 链冒烟）未满足前维持现状。迁移在下游仓执行。
2. **拆接口合并**（A-7，**已裁决：合并弃用**）：`IChannelsBasicTokenFreeService` 式拆接口合并回单接口，免令牌方法改 `[Token(Disabled = true)]`；复刻双向断言（常规方法有 `GetTokenAsync` 调用 + 逃生方法零令牌代码）；旧接口 Obsolete 一版后移除，合并前排查独立 DI 注册。
3. **自建叠层拆除**（A-4/C-1）：两下游可择期拆除"cache + store 写穿"私有叠层，改注册 store 走 B-2 自动桥接；自定义 codec/键映射以显式 `ITokenCache` 注册保留。
4. **Redis 分层迁移**（A-5，**已裁决：分层共存**）：通用 `ITokenStore` 面迁官方包、专属端口留下游包、批删不上收；键前缀不同无需数据迁移。飞书侧 codec 迁移按 C-2 双读 codec（Decode 兼容两种形态、Encode 单写相对秒、免回灌）。
5. **AGENTS.md 增补**：两下游 AGENTS.md 各补一条指向本清单与 CHANGELOG 契约变更专章的引用（约定变更传导通道，防约束漂移）；微信侧另补 B-8（SE.Redis 3.x 超时 catch 口径）升级注意。
