# Mud.HttpUtils 代码注释规范

## 1. 核心原则

### 1.1 注释的职责

✅ **应该做**：
- 解释 **"为什么"**（Why）：当代码意图不明显时，说明背后的约束、边界条件或设计考量
- 说明 **"是什么"**（What）：对复杂算法、非直观行为提供简要概述
- 标注 **"注意什么"**（Warning）：潜在的陷阱、性能瓶颈或安全风险

❌ **不应该做**：
- 复述代码逻辑（"如果条件成立则执行某操作"）
- 记录决策过程（"经过讨论，我们选择了方案 B"）
- 保留历史追踪号（"G7-03 修复"、"M6-HC-12 改进"）
- 包含评审信息（"2026-10-13 评审会议决定"）

### 1.2 黄金法则

> **好的注释让读者少读代码，坏的注释让读者多读废话。**

## 2. XML 文档注释规范

### 2.1 基本结构

```csharp
/// <summary>
/// 一句话概括方法职责（不超过 20 字）。
/// </summary>
/// <param name="name">参数用途及约束。</param>
/// <returns>返回值含义。</returns>
/// <exception cref="ArgumentNullException">抛出条件。</exception>
/// <remarks>
/// 仅在必要时补充：边界条件、异常场景、性能考量。
/// 如需引用设计决策，使用 "详见 ADR-XXX"。
/// </remarks>
```

### 2.2 `<summary>` 规范

**要求**：
- 单句概括，不超过 20 字
- 使用主动语态（"获取用户信息" 而非 "用户信息的获取"）
- 避免技术术语堆砌

**示例**：
```csharp
// ✅ 好
/// <summary>
/// 从配置加载令牌恢复策略。
/// </summary>

// ❌ 差
/// <summary>
/// 基于 IConfiguration 接口的 TokenRecoveryOptions 配置节绑定与验证流程实现。
/// </summary>
```

### 2.3 `<remarks>` 规范

**允许内容**：
- 边界条件（"当参数为 null 时..."）
- 性能考量（"该方法为 O(n) 复杂度..."）
- 线程安全（"非线程安全，调用方需自行同步"）
- ADR 引用（"详见 ADR-012"）

**禁止内容**：
- 历史版本对比（"v2.0 之前使用 TryAddSingleton..."）
- 评审记录（"2026-10-13 评审会议决定..."）
- 多方案权衡（"方案 A 的优点是...缺点是..."）

**长度限制**：单段 `<remarks>` 不超过 100 字，超过则拆分或迁移至 ADR。

**示例**：
```csharp
// ✅ 好
/// <remarks>
/// 生命周期选 Transient，避免多管理器共享缓存键导致串扰。详见 ADR-012。
/// </remarks>

// ❌ 差
/// <remarks>
/// <para>
/// <b>生命周期 = Transient（实施修正，与评审修订的 TryAddSingleton 的差异）</b>：
/// <see cref="ITokenCache{T}"/> 的缓存键为作用域键（<c>ScopeKeyBuilder</c>），<b>不含管理器身份</b> ——
/// 若以 Singleton 产出单个共享实例，多个令牌管理器会共写同一键（如 <c>"default"</c>），
/// 造成跨管理器令牌串扰（安全问题）。Transient 使<b>每个管理器实例持各自缓存</b>，
/// 与"内建缓存"的隔离语义一致；store 侧的键命名空间由 storeKeyMapper / 各自 store 负责
/// （与手动桥接路径的既有约定相同）。
/// </para>
/// </remarks>
```

### 2.4 `<param>` 规范

**要求**：
- 说明参数用途，而非类型（类型已由签名表达）
- 标注约束（取值范围、null 允许性等）

**示例**：
```csharp
// ✅ 好
/// <param name="bufferSize">缓冲区大小（字节），默认 81920，最大 4 MiB。</param>

// ❌ 差
/// <param name="bufferSize">int 类型的缓冲区大小参数。</param>
```

## 3. 行内注释规范

### 3.1 何时使用行内注释

**应该使用**：
- 解释非直观的实现选择
- 标注安全边界（防注入、防溢出等）
- 说明与外部系统的契约（API 格式、协议版本等）

**不应使用**：
- 复述下一行代码的功能
- 标记已完成的任务（除非是进行中的 P0/P1 任务）

### 3.2 注释风格

**格式**：
```csharp
// 简短说明：核心原因或约束
```

**要求**：
- 冒号前概括行为，冒号后说明原因
- 单行不超过 80 字
- 避免缩写和内部黑话

**示例**：
```csharp
// ✅ 好
// CR/LF 注入防护：HTTP 头值含换行符会导致请求走私攻击
if (value.Contains('\r') || value.Contains('\n'))
    throw new ArgumentException(...);

// ❌ 差
// 检查值是否包含回车或换行符
if (value.Contains('\r') || value.Contains('\n'))
    throw new ArgumentException(...);
```

### 3.3 禁用标记

**禁止在行内注释中出现**：
- 开发代号：`G7-03`、`M6-HC-12`、`P1-TK-05`
- 评审标注：`评审修订 7`、`2026-10-13`
- TODO 待删除：`TODO: v4.0 删除`（应纳入 Issue 追踪）

**例外**：进行中的 P0/P1 任务可保留，格式为：
```csharp
// [P1-TK-05] Token 刷新竞态条件修复中，见 2026-10-09-下游消费分析-Bug修复与功能完善方案.md
if (_isRefreshing) return;
```

## 4. 特殊场景规范

### 4.1 复杂算法

**要求**：
- 在方法开头用 `<summary>` 概述算法思路
- 关键步骤用行内注释标注
- 引用学术来源或标准规范（如适用）

**示例**：
```csharp
/// <summary>
/// 使用滑动窗口计算请求速率。
/// </summary>
public double CalculateRate(IEnumerable<DateTime> timestamps)
{
    // 排序确保时间戳递增（防御性编程）
    var sorted = timestamps.OrderBy(t => t).ToList();

    // 滑动窗口：仅保留最近 60 秒的数据点
    var cutoff = DateTime.UtcNow.AddSeconds(-60);
    var window = sorted.Where(t => t >= cutoff).ToList();

    // 速率 = 窗口内请求数 / 窗口时长（秒）
    return window.Count / 60.0;
}
```

### 4.2 安全相关代码

**要求**：
- 明确标注防护的攻击类型
- 说明绕过条件（如有）
- 引用 CWE/CVE 编号（如适用）

**示例**：
```csharp
// SSRF 防护：校验目标 IP 是否为内网地址，防止服务器端请求伪造
// 绕过条件：DNS Rebinding（TOCTOU 漏洞），已通过连接期二次校验缓解
if (!policy.IsAllowed(targetUri))
    throw new SecurityException(...);
```

### 4.3 性能优化

**要求**：
- 标注优化前后的性能差异
- 说明 trade-off（如内存换速度）
- 提供基准测试引用（如适用）

**示例**：
```csharp
// 零分配优化：使用 ArrayPool<byte> 避免频繁 GC
// 基准测试：1000 次迭代减少 15ms CPU 时间，内存分配降低 80%
var buffer = ArrayPool<byte>.Shared.Rent(bufferSize);
```

### 4.4 兼容性代码

**要求**：
- 说明兼容的目标框架或版本
- 标注预计移除时间
- 关联 Issue 编号

**示例**：
```csharp
#if NETSTANDARD2_0
// .NET Standard 2.0 无 CopyToAsync(ct) 重载，改用手动循环携带取消令牌
// 预计移除时间：2027 Q2（停止支持 ns2.0 后）
await CopyToWithCancellationAsync(source, destination, bufferSize, cancellationToken);
#endif
```

## 5. 自动化检查

### 5.1 EditorConfig 规则

```ini
# .editorconfig

# XML 文档注释必须完整
dotnet_diagnostic.CS1591.severity = warning  # 缺少文档警告

# 注释长度限制（通过自定义分析器实现）
mud.comment_max_length = 100
mud.comment_forbidden_patterns = G\d+-\d+|M\d+-HC-\d+|P\d+-.*
```

### 5.2 StyleCop 规则

```xml
<!-- StyleCop.Analyzers 配置 -->
<Rule Id="SA1633" Action="Warning" />   <!-- 文件头部必须有文档 -->
<Rule Id="SA1615" Action="Warning" />   <!-- 返回值必须有文档 -->
<Rule Id="SA1618" Action="Warning" />   <!-- 泛型参数必须有文档 -->
```

### 5.3 自定义检查脚本

```python
# scripts/lint-comments.py
import re
import sys

FORBIDDEN_PATTERNS = [
    r'//\s*(G|M|P)\d+',           # 开发代号
    r'评审修订\s*\d+',             # 评审标注
    r'TODO.*删除',                 # 待删除标记
]

def check_file(filepath):
    with open(filepath, 'r', encoding='utf-8') as f:
        lines = f.readlines()

    violations = []
    for i, line in enumerate(lines, 1):
        if line.strip().startswith('//'):
            for pattern in FORBIDDEN_PATTERNS:
                if re.search(pattern, line):
                    violations.append((i, line.strip(), pattern))

    return violations

if __name__ == '__main__':
    files = sys.argv[1:]
    total_violations = 0

    for filepath in files:
        violations = check_file(filepath)
        for line_no, content, pattern in violations:
            print(f"{filepath}:{line_no}: 违规注释 '{content}' 匹配模式 '{pattern}'")
            total_violations += 1

    sys.exit(1 if total_violations > 0 else 0)
```

## 6. 反模式清单

### 6.1 常见错误

| 反模式 | 示例 | 修正 |
|--------|------|------|
| 复述代码 | `// 如果 x > 0，设置 y 为 x` | 删除或说明原因 |
| 过时注释 | `// TODO: v3.0 删除（当前 v4.2）` | 立即清理 |
| 神秘缩写 | `// Fix EL-9 per TMX-10` | 用自然语言说明 |
| 情绪化注释 | `// 这该死的 bug 终于修了` | 保持专业语气 |
| ASCII 艺术 | `// *************` | 删除或使用标准分隔符 |

### 6.2 反面案例

```csharp
// ❌ 坏例子：注释比代码还长
// 这个方法用于处理用户请求，首先检查参数是否有效，
// 如果无效则抛出异常，否则继续处理。处理过程中需要
// 考虑线程安全问题，所以我们使用了锁机制。另外还要
// 注意性能问题，因此使用了缓存...
public void ProcessRequest(Request req)
{
    lock (_lock) { ... }
}

// ✅ 好例子：简洁明了
/// <summary>
/// 处理用户请求（线程安全）。
/// </summary>
/// <remarks>
/// 使用锁保证并发安全，缓存热点数据提升性能。详见 ADR-008。
/// </remarks>
public void ProcessRequest(Request req)
{
    lock (_lock) { ... }
}
```

## 7. 审查清单

代码审查时，检查以下项：

- [ ] 注释解释了 "为什么"，而非复述 "做什么"
- [ ] 不包含开发代号（G/M/P 系列）
- [ ] 不包含评审日期或参与者信息
- [ ] `<remarks>` 单段不超过 100 字
- [ ] 重大决策已引用 ADR 文档
- [ ] 进行中的任务标记格式正确（`[P1-XXX]`）
- [ ] 无过时或误导性注释
